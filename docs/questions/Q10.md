# Q10 — Outdated guide-data behavior

> **Status:** open
> **Opened:** 2026-11-05 · **Last touched:** 2026-11-05

## The question

What should the addon do when guide data is older than the client or recipe data
conflicts with the saved route?

## Thread

> Append-only.

### 2026-11-05 — opened after grill Round 3

Curated guides depend on maintained expansion/build data. An older validation date
is not proof that a route is broken, but missing/changed prerequisites should not
be silently ignored. Need a user-facing policy distinguishing unverified data from
known incompatible steps, without blocking the independently useful dashboard.

Owner: user and primary for behavior; primary for the compatibility checks themselves.
Blocks guide failure handling, not a requirement for a backend or automated updater.

### 2026-11-05 — grill Round 4 — accepted and promoted

User accepted warnings with validation date for unverified data. Demonstrably
incompatible steps and dependent shopping calculations must be blocked with an
explanation and a validated alternative where available. Dashboard/unaffected guide
sections remain usable. A client-version difference alone does not prove breakage.

→ promoted to D12. Compatibility behavior is decided; the exact checks and route
validation evidence will be specified in implementation/data tasks.
