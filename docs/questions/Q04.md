# Q04 — Auctionator capabilities and export safeguards

> **Status:** open
> **Opened:** 2026-11-05 · **Last touched:** 2026-11-05

## The question

What can the supported Auctionator version's public API represent for shopping
lists, quantities, exact item/quality searches, prices, and repeat exports?

## Thread

> Append-only; add dated evidence rather than rewriting earlier discussion.

### 2026-11-05 — opened

Auctionator shopping lists are confirmed as a product feature; no installed-version
API contract or export round-trip has been verified. The proposal recommends
optional integration, CraftArmy-owned namespaced lists, collision protection,
copyable fallback, unknown-price handling, and explicit disclosure of lost detail.
Do not hardcode an unverified function signature or assume list quantities survive.

Owner: primary for capability research and user for destructive repeat-export policy
if a choice is needed. Blocks the export adapter contract, not internal material math.

### 2026-11-05 — grill Round 3 — single-list policy accepted

User explicitly selected **one reusable `CraftArmy` list**, replaced on a new explicit
export across character/profession/target changes. This supersedes the earlier
proposed per-route namespaced lists. D09 retains optional integration, copyable
fallback, exact internal quantities/qualities, and protection of unrelated lists.
This is a settled product choice, not proof of an external API contract.

### 2026-11-05 — read-only research returned — secondary-source API candidates

Research status **PARTIAL**. The [maintainer release page](https://www.curseforge.com/wow/addons/auctionator)
reports release 341 (2026-10-13), including Retail 12.1.5 support. The linked
[upstream API wiki](https://github.com/Auctionator/Auctionator/wiki/API-Documentation)
and the old upstream raw-source path returned 404; a replacement upstream was not
verified. No installed Auctionator version or live export behavior was tested.

These interfaces are **candidates from maintained consumers/indexed old docs**, not
an authoritative current-release guarantee:

- [skillup-forever consumer, revision 42fb022](https://github.com/cjber/skillup-forever/blob/42fb022a1e73840f8ba7fc255235389c34c676d7/UI/Shopping.lua#L114-L133)
  calls `CreateShoppingList(CALLER,name,searches)` and
  `ConvertToSearchString(CALLER,{searchString=itemName,isExact=true,quantity=item.count})`.
  The consumer states that same-named lists are replaced account-wide. Treat this as
  secondary evidence until the installed implementation is inspected.
- [ShoppingConverter consumer, revision 02dfc31](https://github.com/Tharavol/ShoppingConverter/blob/02dfc31ea58da832012e94f463decef94bf29406/Converter.lua#L138-L156)
  calls `GetShoppingListItems(callerID,listName)` and
  `ConvertFromSearchString(callerID,rawString)`. Missing-list behavior is unverified.
- [Indexed former API docs](https://github-wiki-see.page/m/Auctionator/Auctionator/wiki/API-Documentation)
  describe `tier` as reagent crafting rank, `quality` as item rarity, and `quantity`
  as purchase preselection. Direct retrieval redirected to the unavailable upstream.
  No current direct item-ID shopping field was confirmed; do not conflate `tier`
  with rarity or assume old 1–3-tier documentation covers every current item.
- Indexed former docs list `GetAuctionPriceByItemID(callerID,itemID)` and
  `GetAuctionPriceByItemLink(callerID,link)` as last-scanned copper prices or `nil`.
  The current scan-price freshness contract remains unknown.

Safeguards to specify in the eventual task: construct/validate the full export before
mutating the list, disclose an unowned existing `CraftArmy` name collision before
takeover, never write Auctionator internals, and never change unrelated lists.
Avoid automatic multisearch until verified: a
[consumer issue](https://github.com/RussellFeinstein/guild-bank-ledger/issues/194)
reports creation/replacement of an additional temporary list, conflicting with the
single-owned-list intent.

Future approval-gated checks: installed API/version, repeat replacement across alts,
collision/readback behavior, empty-list exports, quantities, exact names/quality tiers,
partial-failure behavior, and price coverage/freshness. Q04 stays open for facts,
not for reselecting the accepted single-list policy.

### 2026-11-05 — T01 capability-only implementation delivered

The approved diagnostic records Auctionator namespace/method presence and version,
but invokes **no Auctionator methods**, including readback, because the installed
public signature is not verified. It creates/replaces/deletes no list and performs
no search or purchase. Unsupported readback is not an observed empty list.

Static review found no concrete blocking defect; no live Auctionator session or
round-trip behavior was tested. Q04 remains open. The agreed single reusable
`CraftArmy` list stays D09; a mutating export test requires separate approval.

### 2026-11-05 — first client presence evidence

User's diagnostic report shows Auctionator 341 loaded, API.v1 present, and candidate
`GetShoppingListItems`/`ConvertFromSearchString` methods present. The harness invoked
none of them and reports readback unsupported. This verifies reported namespace and
method presence only, not signatures, successful readback, replacement behavior, or
disabled-addon handling. Q04 remains open; no list mutation is authorized.
